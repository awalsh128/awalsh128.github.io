# Site internals

Generated content, the resume, and theme overrides.

## Backgrounds

Post, list, and tag pages get a background picked at random on each load from `assets/img/backgrounds/*.jpg`
(see `layouts/partials/random-background.html`); add or remove a .jpg there to change the rotation. The
homepage keeps `assets/img/header.jpg`.

## CSS

Site CSS overrides live in `assets/css/custom/`, one file per responsibility, and are bundled into
`css/custom.css` by `layouts/partials/extend-head.html` in filename order. Add rules to the matching file (or
a new numbered one); don't recreate `assets/css/custom.css`.

## Homepage projects

The project list in `content/_index.md` is generated by `scripts/update_projects.py` from its `REPOS` dict, in
a collapsed `<details>` block between the `projects:start` and `projects:end` markers. `REPOS` maps a group
name (rendered as a heading, e.g. "Libraries") to its repositories; add a group or move a repository by
editing it. The script also downloads each project's README logo to `assets/img/projects/` (shown by the
`project-icon` shortcode). Don't edit either by hand; edit `REPOS` or the README logos on GitHub instead.

## Homepage Posts section

`layouts/partials/recent-articles/main.html` replaces Blowfish's "Recent" list with a "Posts" section of
`homepage.showRecentItems` cards, in this order:

1. Pinned posts (`pinned: YYYY-MM-DD` in front matter), most recently pinned first. AGENTS.md covers reviewing
   pins.
2. The most popular posts: most Google Search clicks in the latest export, from `data/popular_posts.json`.
3. The newest posts, filling any remaining slots.

`scripts/update_popular_posts.py` writes `data/popular_posts.json` from a Search Console export, and the
pre-commit hook runs it. To refresh the ranking, open Search Console > Performance > Pages for the
`awalsh128.com` property, pick a date range (a year is a good default), and click Export > Download CSV; the
zip lands in `~/Downloads`, and the next commit picks up the newest one. Without an export the data file stays
as it is, and with no data the section shows the newest posts.

## API page

The library list in `content/api.md` is generated by `scripts/update_apis.py` between the `apis:start` and
`apis:end` markers, and the pre-commit hook regenerates it. A repository is listed when it's public, not a
fork or archived, has GitHub Pages enabled, and its homepage is `https://www.awalsh128.com/<repo>/`. To add or
remove a library, change its repository's homepage or Pages setting on GitHub, not the page. npm links come
from the root `package.json`, or from each workspace listed explicitly (not by glob) when the root is private.

## Resume

`content/resume.md` is the single source of the resume. Never move it to another repo or point the homepage
link elsewhere. Update it with `scripts/resume_to_md.py`. It renders with `layouts/_default/resume.html`, and
`content/resume.pdf` is generated from the page by `scripts/resume_to_pdf.sh` (run by the pre-commit hook when
the resume, its layout, or `assets/css/custom/` is staged); don't edit the PDF by hand.

The page shows LinkedIn recommendations under References, from `data/linkedin_recommendations.json`. The
pre-commit hook refreshes it with `scripts/update_recommendations.py`, which reads only
`Recommendations_Received.csv` from the newest LinkedIn data export in `~/Downloads` (LinkedIn has no API for
this). They're hidden in print, so the PDF leaves them out. Don't edit the JSON by hand.
