# Site internals

Generated content, the resume, and theme overrides.

## Backgrounds

Post, list, and tag pages get a background picked at random on each load from `assets/img/backgrounds/*.jpg` (see
`layouts/partials/random-background.html`); add or remove a .jpg there to change the rotation. The homepage keeps
`assets/img/header.jpg`.

## CSS

Site CSS overrides live in `assets/css/custom/`, one file per responsibility, and are bundled into `css/custom.css` by
`layouts/partials/extend-head.html` in filename order. Add rules to the matching file (or a new numbered one); don't
recreate `assets/css/custom.css`.

## Homepage projects

The project list in `content/_index.md` is generated by `scripts/update_projects.py` from its `REPOS` dict, in a
collapsed `<details>` block between the `projects:start` and `projects:end` markers. `REPOS` maps a group name (rendered
as a heading, e.g. "Libraries") to its repositories; add a group or move a repository by editing it. The script also
downloads each project's README logo to `assets/img/projects/` (shown by the `project-icon` shortcode). Don't edit
either by hand; edit `REPOS` or the README logos on GitHub instead.

## Homepage Posts section

`layouts/partials/recent-articles/main.html` replaces Blowfish's "Recent" list with a "Posts" section of
`homepage.showRecentItems` cards, in this order:

1. Pinned posts (`pinned: YYYY-MM-DD` in front matter), most recently pinned first. AGENTS.md covers reviewing pins.
2. The most popular posts: most Google Search clicks over the last year, from `data/popular_posts.json`.
3. The newest posts, filling any remaining slots.

`scripts/update_popular_posts.py` writes `data/popular_posts.json` from the Search Console API for the
`sc-domain:awalsh128.com` property, as a service account. The pre-commit hook runs it with a local JSON key, and CI
refreshes it on each build (including the weekly one) through Workload Identity Federation, with no stored key. Both
skip it without access and keep the committed data; with no data the section shows the newest posts. One-time setup:

1. In Google Cloud, create a project, enable the Search Console API, and create a service account.
2. In Search Console, add the service account's email as a user (Restricted) on the `awalsh128.com` domain property.
3. CI: create a Workload Identity pool with a GitHub OIDC provider limited to `awalsh128/awalsh128.github.io`, and let
   it impersonate the service account (`roles/iam.workloadIdentityUser`). Set the repository variables
   `GCP_WORKLOAD_IDENTITY_PROVIDER` (the provider's full resource name) and `GCP_SERVICE_ACCOUNT` (its email).
4. Local (optional): create a JSON key for the service account and save it as
   `~/.config/awalsh128.com/search-console-key.json`, or point `$SEARCH_CONSOLE_KEY` at it. Keep it out of the repo.

## API page

The library list in `content/api.md` is generated by `scripts/update_apis.py` between the `apis:start` and `apis:end`
markers, and the pre-commit hook regenerates it. A repository is listed when it's public, not a fork or archived, has
GitHub Pages enabled, and its homepage is `https://awalsh128.com/<repo>/`. To add or remove a library, change its
repository's homepage or Pages setting on GitHub, not the page. npm links come from the root `package.json`, or from
each workspace listed explicitly (not by glob) when the root is private.

## Resume

`content/resume.md` is the single source of the resume. Never move it to another repo or point the homepage link
elsewhere. Update it with `scripts/resume_to_md.py`. It renders with `layouts/_default/resume.html`, and
`content/resume.pdf` is generated from the page by `scripts/resume_to_pdf.sh` (run by the pre-commit hook when the
resume, its layout, or `assets/css/custom/` is staged); don't edit the PDF by hand.

The page shows LinkedIn recommendations under References, from `data/linkedin_recommendations.json`. The pre-commit
hook refreshes it with `scripts/update_recommendations.py`, which reads only `Recommendations_Received.csv` from the
newest LinkedIn data export in `~/Downloads` (LinkedIn has no API for this). They're hidden in print, so the PDF leaves
them out. Don't edit the JSON by hand.
